# Возможности

По назначению yactl похож на systemd, OpenRC и другие менеджеры сервисов:
он запускает программы и следит за их работой. Дополнительно он предоставляет
локальный API оборудования колонки. Поведение
приложений остаётся снаружи: например, отдельный клиент подсветки рисует эффекты отдельным процессом.

## Менеджер сервисов

Программы запускаются на переднем плане. Для каждой задаются аргументы, рабочий
каталог, окружение, политика перезапуска и ограничения логов. Менеджер умеет
останавливать группу процессов, повышает задержку после повторных сбоев и
сохраняет записи сервисов между запусками.

[Команды управления](../guide/services.md) позволяют менять текущий запуск и автозапуск
отдельно. API работает собственным сервисом `yactl-api`; его сбой не должен
останавливать остальные приложения.

## Оборудование Миди

| Ресурс | Доступ |
| --- | --- |
| RGB-кольцо и логотип | Полные кадры с временным владением и восстановлением |
| Белые сегменты часов | Время HH:MM или отдельные сегменты |
| Громкость | Линейный уровень ALSA, постоянное или временное изменение |
| Датчики | Кэшированные показания с единицами и возрастом |
| Кнопки и переключатели | Состояние, события, восстановление после потери очереди |
| События прошивки | Чтение известных сообщений aliced/alarmd |

Подробности протоколов — в [API](../api/index.md), реальный объём проверок — в
[поддержке](support.md). Наличие реализации не означает проверку на любой прошивке.

## Доступ и конфигурация

API доступен через приватный Unix-сокет и HTTP на loopback. Удалённый HTTP
включается явно и требует разрешений. Чтение, изменение оборудования и управление
сервисами разделены на scopes. Настройки проверяются до применения; некорректный
reload оставляет работающую конфигурацию.

## Приложения

Эффекты и автоматизации работают отдельными программами и используют
версионированный API. Необязательный веб-интерфейс пока в планах.
