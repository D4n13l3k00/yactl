# Устройство и состояние

Все три маршрута требуют `read` по HTTP и доступны владельцу приватного сокета.

## `GET /v1/health`

Сообщает готовность API, менеджера и настроенных адаптеров. `ready` относится
к API-процессу, `supervisor.ready` — к живому ответу менеджера в пределах 250 мс.
Для каждого адаптера различаются `supported` и `ready`: исторически проверенный
интерфейс может быть сейчас недоступен. Ошибки отражаются отдельно.

Для прошивки одного TCP-подключения недостаточно: источник становится
проверенным только после распознанного сообщения. После переподключения нужно
новое сообщение для текущей готовности.

## `GET /v1/device`

Постоянный локальный ID не зависит от IP и hostname. Изменяемые имя и модель
отделены от исходных сведений обнаружения. Модель можно переопределить как
`midi` или `unknown`; это не включает аппаратные адаптеры.

`model_source` указывает происхождение модели. Данные device-tree сохраняются
в `evidence`. Метаданные прошивки сейчас означают OS `ID`/`VERSION_ID` из
`/etc/os-release` и версию ядра. Неизвестные значения — null. Ревизия платы
извлекается только из распознанной строки Cucumber.

## `GET /v1/capabilities`

Возвращает проверенные операции, геометрию и ограничения. Не выводите поддержку
по названию колонки. При выключенных адаптерах список пуст. Симуляция помечена
отдельно и не доказывает физическую совместимость.

Эквиваленты CLI:

```sh
yactl --json health
yactl --json device
yactl --json capabilities
```
