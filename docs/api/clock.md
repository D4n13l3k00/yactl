# Часы Cucumber

Часы — отдельный от RGB ресурс. Используются общий механизм владения, один
ожидающий кадр и срок активности 1000 мс. По умолчанию `clock.backend` равен
`off`; доступны `simulate` и `sysfs`. Смена требует перезапуска API. Reload
отклоняет её, сохраняя активные настройки.

## Запросы

`GET /v1/clock/status` требует `read`, `POST /v1/clock/stream` — `hardware`.
Поток использует `application/x-ndjson`, в том числе HTTP chunked. Владелец
приватного Unix-сокета имеет эти разрешения; HTTP-клиенту нужен подходящий токен.

```json
{"sequence":1,"time":"12:34","brightness":60}
{"sequence":2,"segments":{"a1":120,"p3":60,"q3":60}}
```

`time` строго соответствует 24-часовому `HH:MM`. Яркость — целый байт, по
умолчанию 170. Сегментный кадр заменяет весь дисплей: пропущенные сегменты
обнуляются. Временной кадр также очищает лишние маркеры. Имена — фиксированные
строчные обозначения Cucumber из возможностей API, а не произвольные пути.
Нельзя одновременно передавать `time` и `segments`.

Аппаратные ограничения яркости проверяются до очереди. Возможности сообщают
безопасный общий `brightness_max` и отдельные `brightness_limits`, прочитанные
из sysfs. Размер записи — 4096 байт. Сроки, порядок номеров и освобождение
при разрыве соответствуют [RGB-потоку](lighting.md).

Пока часы заняты, отправляйте кадры чаще срока активности. Один запрос не
заменяет часы прошивки навсегда. RGB и часы захватываются независимо.

## Аппаратный адаптер

Принимается только полный известный набор: 45 белых сегментов и два sync-узла.
Проверка читает значения и пределы, открывает дескрипторы записи, но не меняет
дисплей. Поддержка не объявляется до успешного обнаружения. Перед записью
и восстановлением sync-узлы сбрасываются в ноль.

При захвате сохраняется текущий дисплей. Освобождение восстанавливает его, только
если текущее состояние ещё совпадает с последней записью адаптера. Более новый
вывод прошивки сохраняется; следующий корректный кадр захватывает его как новую
базу восстановления. Полный кадр проверяется до записи. После частичной ошибки
откатываются только сегменты, всё ещё совпадающие с нашей попыткой; ошибка отката
сообщается явно. Неопределённое состояние делает адаптер недоступным для новых записей.

Записи sysfs не атомарны как группа. Восстановление не гарантируется при конкуренции
прошивки, SIGKILL, потере питания или зависшем вызове ядра. Перезапуск рабочего
процесса не восстанавливает снимок из памяти предыдущего.

Обычные тесты используют симуляцию, временный sysfs и внедрение ошибок. На колонке
проверены время и яркость, чтение всех сегментов и sync-узлов и точное восстановление
при штатном освобождении. См. [результаты](../development/verification.md).
