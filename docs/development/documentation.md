# Работа над документацией

Сайт собирается из `/docs` с помощью MkDocs Material. Интерфейс и тексты на
русском; команды, поля JSON и коды ошибок сохраняют исходное написание.

## Локальный просмотр

Из корня репозитория:

```sh
python3 -m venv .venv-docs
.venv-docs/bin/pip install -r requirements-docs.txt
.venv-docs/bin/mkdocs serve
```

Откройте `http://127.0.0.1:8000`. Для итоговой проверки:

```sh
.venv-docs/bin/mkdocs build --strict
```

Результат находится в `site/` и не добавляется в Git. Основные версии MkDocs
и Material закреплены в `requirements-docs.txt`. Настройки — в `mkdocs.yml`,
цвета и адаптивные стили — в `docs/stylesheets/extra.css`.

## Структура

- «Обзор» отвечает, что умеет проект и на каких устройствах это проверено.
- «Установка и запуск» ведёт от бинаря CI к настройке и управлению сервисами.
- «API» описывает доступ, маршруты и точные правила ресурсов.
- «Разработка» содержит сборку, тесты, архитектуру и выпуск.
- «Испытания и решения» хранит протоколы и план, не отвлекая новичка от установки.

Новую страницу добавляйте в подходящий раздел `nav`. Сначала объясняйте задачу
и шаги пользователя, затем ограничения. Не называйте симуляционный тест
аппаратной проверкой. Для API сохраняйте типы, размеры, сроки, разрешения и ошибки.

`docs_hooks.py` включает исходные init-скрипт, пример настроек и fish-файл как
скачиваемые файлы сайта. Он преобразует ссылки на эти исходники при сборке;
отдельные копии примеров в документации не поддерживаются.

## GitHub Pages

После публикации репозитория откройте **Settings → Pages → Build and deployment**
и выберите **GitHub Actions** как источник. Workflow **Documentation** проверяет
pull request без публикации; push в `master` собирает и публикует сайт.

Адрес и ссылка на репозиторий вычисляются из текущего GitHub-репозитория, без
привязки к владельцу. По умолчанию адрес имеет вид
`https://OWNER.github.io/REPOSITORY/`. Для пользовательского домена или особой
схемы Pages задайте `YACTL_SITE_URL` в workflow и настройте домен отдельно.
Для репозитория `OWNER.github.io` нужен адрес без суффикса имени репозитория.

Deploy-job использует окружение `github-pages`, `pages: write` и `id-token: write`;
build-job имеет только чтение исходников. Публикация с чужих pull request не
выполняется. Создание workflow не подтверждает, что Pages уже включён или сайт
опубликован: нужен первый успешный запуск в целевом репозитории.
