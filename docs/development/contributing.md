# Участие в разработке

Перед изменением границ процессов, контрактов API или владения ресурсами
прочитайте [архитектуру](architecture.md). Объясняйте, какое поведение исправляет
изменение, какие проверки выполнены и на какие аппаратные испытания вы опираетесь.

Обычные тесты используют симуляцию или временный sysfs. Физическая колонка не
должна быть обязательной для unit-тестов. Аппаратные изменения нужно проверить
на устройстве прежде, чем называть их проверенными. При развёртывании сохраняйте
SSH и существующую конфигурацию.

Сообщения CLI, ошибки API и имена протокольных полей остаются на английском.
Не добавляйте зависимости от исходников другого приложения: отдельный клиент подсветки и другие
клиенты используют версионированный API.

Перед отправкой выполните [проверки](index.md#проверки). Описывайте новый
API рядом с реализацией. Не публикуйте сырые логи устройства, расшифровки речи,
конфигурацию прошивки или секреты. Для отчётов используйте синтетические данные
и очищенные шаги воспроизведения.
