# Управление сервисами

Сервис — существующая программа, которая остаётся на переднем плане. yactl
запускает её, отслеживает процесс и при необходимости перезапускает.

## Добавление и состояние

```sh
yactl services add my-agent -- /data/opt/local/bin/my-agent
yactl services list
yactl services status my-agent
yactl services show my-agent
yactl services logs my-agent --follow
```

`add` запускает сервис и включает старт вместе с менеджером. Для записи без
запуска и автозапуска добавьте `--disabled`. Аргументы программы идут после `--`.
Рабочий каталог задаётся `--cwd`, окружение — повторяемым `--env KEY=VALUE`.
Не публикуйте вывод `show`, если в окружении хранятся секреты.

## Перезапуск и остановка

```sh
yactl services restart my-agent
yactl services stop my-agent
yactl services start my-agent
yactl services disable my-agent --now
yactl services enable my-agent
```

Политика `--restart` принимает `always`, `on-failure`, `never`. Задержка повторов
и срок остановки настраиваются через `--restart-delay-ms` и `--stop-timeout-ms`.
После TERM менеджер ждёт, затем использует KILL для группы процессов. Логи
ограничены и ротируются; размер задаётся `--log-max-kib`.

`enable` и `disable` задают старт вместе с менеджером, а не системный init-хук.
Для загрузки самой службы при включении колонки нужна
[настройка автозапуска](installation.md#автозапуск).

Остановленный сервис можно удалить, сохранив его логи:

```sh
yactl services stop my-agent
yactl services remove my-agent
```

Записи JSON перечитываются отдельно от общей конфигурации:
`yactl services reload NAME`. Префикс `services` необязателен; например,
`yactl status` и `yactl services status` используют один контракт.

## API-процесс и HTTP

Менеджер создаёт `yactl-api` автоматически, сохраняя уже существующую запись.
Его можно останавливать и перезапускать отдельно. `yactl shutdown` останавливает
все сервисы и менеджер.

`POST /v1/services/request` принимает существующие JSON/RPC-запросы управления.
Требуется scope `services`. Этот маршрут может запускать программы, поэтому
его разрешение не выдаётся клиентам, которым нужно только оборудование.
Не более четырёх блокирующих пересылок выполняются одновременно; перегрузка
возвращает HTTP 503. Примеры обычного использования выше используют тот же
контракт через CLI, без необходимости формировать RPC вручную.
